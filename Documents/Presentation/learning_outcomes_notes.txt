Learning Outcomes for the VR Computer Architecture Prototype

Purpose:
- these outcomes are meant to describe what the current project actually teaches
- they are phrased so they can be reused in the presentation and later in the thesis
- they are informed by external computer-architecture learning materials, but trimmed to match the implemented scope of the build

Final proposed learning outcomes

1. Decode the relevant fields of a supported single-cycle MIPS instruction.
- In practice, this means identifying opcode, source registers, destination register where relevant, immediate field where relevant, and funct field for R-type instructions.
- Project coverage:
  - Learning mode decode
  - Practice mode typed binary-field decode
  - Test mode strict decode

2. Explain the role of the major datapath components involved in instruction execution.
- This includes the register file, ALU, multiplexers, sign-extension path, data memory, and PC update logic.
- Project coverage:
  - guided Learning mode
  - reduced-support Practice mode
  - instruction coverage across arithmetic, immediate, memory, branch, and jump categories

3. Trace an instruction and its data through the major stages of a single-cycle datapath.
- The learner should be able to follow the instruction through IF, ID, EX, MEM, WB, and PC update, while recognizing that not every instruction meaningfully uses every stage in the same way.
- Project coverage:
  - routed world-space phase stations
  - fetch flow
  - decode register scanning
  - ALU, memory, write-back, and PC update stations

4. Select the correct operands and control-facing choices needed to complete execution of a supported instruction.
- The learner should be able to choose the right registers, immediate handling, ALU behavior, memory action, write-back target, and next-PC path for the supported instruction set.
- Project coverage:
  - decode scanner logic
  - immediate extender
  - ALU interaction
  - memory phase validation
  - write-back validation
  - PC update validation

5. Predict the architectural state changes caused by a supported instruction.
- The learner should be able to anticipate the resulting changes to registers, data memory where relevant, and the program counter / next-PC path.
- Project coverage:
  - persistent register bank
  - memory-bank updates
  - branch and jump handling
  - end-state validation in later phases

6. Compare how different instruction classes change datapath behavior.
- The learner should be able to contrast the execution flow of R-type, immediate, load/store, branch, and jump instructions inside the same single-cycle CPU model.
- Project coverage:
  - three-mode structure built on the same world and datapath stations
  - authored instruction set spanning:
    - R-type
    - immediate
    - load/store
    - branch
    - jump

7. Complete a supported instruction walkthrough with reduced or no guidance.
- This is the practical culmination of the earlier outcomes and matches the shift from Learning to Practice to Test.
- Project coverage:
  - Learning mode scaffolding
  - Practice mode reduced support
  - Test mode strict independent completion

What should not be claimed

Do not claim that the current build teaches:
- full MIPS coverage
- pipelining or hazard handling
- multicycle execution
- full assembly programming
- full controller design from scratch

These are outside the current project scope.

Recommended teaching sequence

The cleanest educational progression is:
- decode
- explain
- trace
- select
- predict
- compare
- complete independently

This aligns well with the three-mode structure:
- Learning emphasizes decode, trace, and explain
- Practice emphasizes select, predict, and compare
- Test emphasizes independent completion

Presentation-use version

If the slide needs a short visible version, use:

- Decode the relevant fields of a supported single-cycle MIPS instruction.
- Explain the role of the major datapath components involved in instruction execution.
- Trace an instruction and its data through the major stages of a single-cycle datapath.
- Select the correct operands and control-facing choices needed to execute an instruction.
- Predict the architectural state changes caused by a supported instruction.

Thesis-use version

If the thesis needs a slightly fuller version, use outcomes 1 through 6 above and then explicitly state that the current system is scoped to a guided single-cycle MIPS baseline rather than a full architectural curriculum.
